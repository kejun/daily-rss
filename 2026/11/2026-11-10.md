### 1. 企业 AI 的真正瓶颈是信任，不是技术

Cisco 最新研究《Permission to…》的核心结论：AI 现在能做的事，远超大多数组织允许它做的事，能力不再是约束条件。文章把企业采用曲线拆成"能力—许可—信任"三段，指出 2026 年的分水岭是**谁愿意为 agent 的行为签字**。对做企业级 agent 的团队，这是比任何 benchmark 都更重要的产品定义依据。
[阅读原文](https://siliconangle.com/2026/11/09/cisco-research-trust-not-technology-is-now-the-speed-limit-on-enterprise-ai/)

### 2. AI 繁荣里被忽略的资产负债表问题：什么被真正验证过？

作者在纽交所 floor 待了 13 年，他提出的框架很锋利：一笔交易可以既被执行、被记录、完全合法，同时其背后的假设是错的。当前 AI 基础设施承诺的增速，已经快于"合同产能 → 持续经济价值"这条证据链的建立速度。文中点名 neocloud 的长约收入确认方式，值得每个看 AI 基建标的的人读一遍。
[阅读原文](https://siliconangle.com/2026/11/06/the-ai-booms-missing-balance-sheet-question-what-has-actually-been-verified/)

### 3. 用"逆向博弈论"约束 AI Agent

MIT Tech Review 介绍的 mechanism design 思路：不靠事后惩罚，而是设计一套激励结构，让强大模型"自愿"守规矩。这与当前主流的 RLHF / 宪法 AI 是两条不同路径——前者改动机，后者改偏好。文章也坦承局限：机制设计假设参与者理性，而 LLM 的"理性"本身仍是未解问题。
[阅读原文](https://www.technologyreview.com/2026/11/03/1147934/reverse-game-theory-mechanism-design-ai-alignment/)

### 4. 停止数 token，开始数交付

一篇关于 agent 经济学的文章：一个编码 agent 完成单任务可能消耗基础对话 10-50 倍的 token，但它交付的是"能跑的代码"而非"一段回答"。用 token 计量 agent 成本，就像用字数给工程师计薪。真正该跟踪的指标是"每次成功交付的成本"。
[阅读原文](https://www.technologyreview.com/2026/11/02/1147702/stop-counting-tokens-start-counting-what-ships/)

## 📊 论文精选

### 1. Test-Time Compute Scales Better with Parallel Agent Teams
提出"并行 agent 团队"：与其 Best-of-N 采样多个独立 agent（很快饱和），或让一个大团队协作（规模增大后停滞），不如并行采样多个**小团队**、保留最佳团队结果。在 12 个长程任务（GPU kernel 编写、形式化证明等）上验证，test-time compute 的缩放效率显著优于两种基线。这对 agent 系统的工程预算分配有直接指导意义。
[arXiv:2611.09798](https://arxiv.org/abs/2611.09798v1)

### 2. BitDecoding-FP4: Native FP4 KV Cache Decoding via Algorithm-System Co-Design
长上下文服务的 KV cache 是内存与带宽的主要消耗者。现有 FP4 KV 方案要么用朴素量化导致精度崩塌，要么用向量码本导致查表开销拖垮吞吐。本文做算法—系统协同设计，在 NVFP4/MXFP4 张量核上实现既准确又高效的原生 FP4 解码。这是"长上下文成本"这条主线上的硬核进展。
[arXiv:2611.09825](https://arxiv.org/abs/2611.09825v1)

### 3. When Instruction Files Go Stale: Documentation Debt and Hidden Cost in Coding Agents
把 AGENTS.md / CLAUDE.md 这类仓库指令文件的过期问题，正式定义为"文档债"，并量化其"利息"：每次 agent 会话都在为过期指令付出代价。关键发现是——只看任务成功率的评测完全看不到这笔成本，过期文件可以长期潜伏。这是每个用 Claude Code / Codex 的团队都该读的一篇。
[arXiv:2611.09802](https://arxiv.org/abs/2611.09802v1)

### 4. MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory
系统追踪"记忆投毒"的生命周期：某次会话中遇到的恶意指令被写入记忆，在后续会话被检索并执行。不同记忆架构（摘要式、检索式、图结构）的受影响程度差异巨大。随着 agent 长期化，这会成为一个标准的安全评测项。
[arXiv:2611.09721](https://arxiv.org/abs/2611.09721v1)

### 5. On Agentic Manipulation Policies
反直觉结论：通用 AI 模型直接控制机械臂，比专门训练的 VLA（视觉-语言-动作）与世界-动作模型更可靠。作者提出 AMP1 参考框架，同一套代码在单臂、双臂、移动操作上均达 SOTA。如果这个结论成立，机器人领域的"专用模型"路线需要重新论证。
[arXiv:2611.09892](https://arxiv.org/abs/2611.09892v1)

## 💡 编者观察

今天这份素材读下来，最强烈的感受是：**AI 行业正在同时经历"能力过剩"和"合法性赤字"**。

一边是能力曲线的陡峭上升。Anthropic 的 Fable 5.2 在 Artificial Analysis 上刷到 65 分，百度 ERNIE Evolve 已经能自主改代码、跑实验、只保留被验证的提升，Meta 的 Muse Ember 把 agent 执行成本压到 10 美分/百万 token，DeepX 宣称 5W 就能跑 100B 参数推理。技术侧的进展没有任何放缓迹象，甚至在"AI 改进 AI"这条最敏感的路上，METR 已经开始用 Anthropic 的内部数据做风险评估——这本身就是一种承认。

另一边是合法性在快速流失。美国中期选举里 41 项数据中心公投，40 项投给了限制；科技股一天蒸发 2.5 万亿美元市值；Anthropic 不得不花 34 亿美元买天然气涡轮机，因为电网接不进去；英伟达 CEO 的私人关系演变成国家安全调查，董事会启动独立审查，一家市值数万亿美元的公司，其中国战略的游说空间被一条情报备忘录彻底锁死。Cisco 的研究说得最准：**AI 现在能做的事，远超组织允许它做的事，瓶颈是信任，不是技术。**

这两条线交汇的地方，就是今天最值得注意的信号：**行业重心正在从"模型能力"迁移到"agent 的工程约束"**。看看今天的 GitHub Trending 就明白了——agent-browser、Cloudflare 的 security-audit-skill、Google/Anthropic/MattPocock 的 skills 仓库、Meta 的 astryx 设计系统，五个项目全都在解决"怎么让 agent 在边界内可靠工作"。再看产品侧：Reason Machines 开源了给 agent 用的 Git 服务器，Anthropic 在研究 agent 该怎么决定"什么值得记住"，Uber 建了治理 800 个 MCP server 的网关，GitLab 把 agentic 开发纳入审计体系。这些不是在提升能力，是在**建造笼子**。

而笼子本身正在成为新的攻击面。Claude Code 的"不再询问"选项把成千上万个密钥写进了可提交的配置文件；Qubole 客户的供应链被横向穿透；MemoryDojo 那篇论文证明，一次会话里的恶意指令可以被写进记忆、在几周后的另一次会话里执行。我们给 agent 修的每一条便利通道，都同时是一条入侵通道。

所以我对明年的判断是：**赢家不会是模型最强的公司，而是最先把"可审计、可回滚、可问责"做成产品默认值的公司**。这也解释了为什么 OpenAI 要买 Pierre、Meta 要买 Conductor、Salesforce 花 27 亿买 Cresta——他们买的不是能力，是"控制点"。

最后说一句不那么技术的话。Jim Nielsen 这周引了 Bill Gates 的一句：我们可能需要培养"不去最大化使用技术"的品味。Dense Discovery 这期的标题是"组织不满"。Ben 说"没人真的知道方向"。三份完全不同领域的 newsletter，在同一周指向同一件事：**当技术供给远超需求时，稀缺的就不再是能力，而是判断力。** 而判断力这种东西，恰好是没法用 token 计价的。
