## 🔥 核心主题

### 一、AI 资本开支进入"公开市场买单"阶段

过去两年，AI 基建的钱主要来自三处：超大规模厂商的经营现金流、私募债、以及供应商的资产负债表兜底。这周出现了第四种：**直接在公开市场发股票和债券**。

**Oracle 申请发行 200 亿美元新股与债券**，明确用于 AI 数据中心建设。这条新闻在 HN 拿到 98 分、56 条评论，讨论的焦点不是 Oracle 能不能建成，而是"当一家以稳定现金流著称的企业软件公司开始用股权融资买 GPU，这个循环里的最后一环是谁"。
→ https://www.cnbc.com/2026/11/02/oracle-files-to-sell-20-billion-in-new-stock-bonds-to-finance-ai-buildout.html

**TechCrunch 的判断更直接**：《AI 支出热潮的裂缝正在出现》。文章把三条线并置——债务规模上升、自由现金流为负、投资者怀疑加剧——结论是"Big Tech 仍在砸钱，但市场开始要求看到单位经济学"。
→ https://techcrunch.com/2026/10/30/cracks-are-emerging-in-the-ai-spending-boom/

**最刺眼的一笔账来自 Anthropic 自己**。Business Insider 报道：Anthropic 内部使用 Claude 的 token 量，按零售 API 价格折算，成本已经超过公司支付给全体员工的工资。HN 上 247 分、202 条评论，最高赞的观点是"这不是浪费，这是最诚实的产品 dogfooding——但它也说明，如果 AI 真的替代人力，省下来的钱会先被 token 账单吃掉"。
→ https://www.businessinsider.com/anthropic-claude-internal-ai-use-exceeds-employee-pay-tokens-2026-11

**消费端也开始限流**。Elon Musk 以"成本不可持续地高"为由，对 Grok Bot 实施更严格的用量限制。一个刚被称为"我见过增长最快的产品"的东西，两周内就要靠限流控成本，这个反差本身就是 2026 年 AI 产品的标准生命周期。
→ https://techcrunch.com/2026/11/02/elon-musk-throttles-grok-bot-limits-due-to-unsustainably-high-costs/

### 二、Agent 安全事故从"模型太聪明"转向"没人记账"

本周的四个案例彼此无关，但指向同一个结构性缺陷。

**ChatGPT 账号可以被接管**。Parameter Labs 披露了一条相当复杂的攻击链：ChatGPT 的 artifacts（HTML 预览）在沙箱 iframe 中运行，而 OpenAI 用于图表渲染的 MathLive 库存在可被利用的接口，攻击者可借此让沙箱内的代码触达 OpenAI API 与用户私有数据，最终实现账号控制。Simon Willison 的点评是："这不是提示注入，这是经典的 Web 安全漏洞，只不过发生在 AI 产品里。"
→ https://simonwillison.net/2026/Oct/31/how-we-took-over-chatgpt-accounts/

**国防承包商的个人 Claude agent 在五角大楼网络里跑了两个月**。WIRED 报道，Accenture 一名员工的私人 agent 在 DOD 网络上持续运行，直到被发现并修补。"个人 agent + 企业网络 + 无登记"这个组合，几乎是所有 agent 治理框架的反面教材。
→ https://www.wired.com/story/a-defense-contractor-gave-their-personal-ai-agent-access-to-a-secure-pentagon-system/

**Anthropic 官方 Cursor 扩展被植入后门近 12 小时**，攻击者如何取得 Anthropic 已验证的 Cursor 账号发布权限，至今不明。供应链攻击第一次以"AI 编程工具"为靶心。
→ https://arstechnica.com/security/2026/10/anthropic-vs-code-extension-on-cursor-backdoored-for-nearly-12-hours/

**学术界给出更悲观的版本**：arXiv 论文《Agentic backdoors via pretraining poisoning》在 HN 拿到 64 分，论证了预训练阶段的数据投毒可以在模型内部埋下"agent 模式下才激活"的后门——常规安全评测几乎无法发现。
→ https://arxiv.org/abs/2610.37741

MIT Technology Review 的评论文章把这一切总结成一句极准的话：**我们急着给 agent 授权，却没有给它配一本账。**
→ https://www.technologyreview.com/2026/10/29/1147824/monitor-ai-agents-actions-real-time/

### 三、开放权重继续"往下压"：这一轮是科学、语音和本地决策

**Hydrogen-1.0：753B 的科学发现模型**。Deep Principle 在 Z.ai 的 GLM-5.3 上做领域后训练，喂的是化学、材料、生命科学的实验室记录与 agent 探索轨迹，最终以 MIT 许可开源。官方称在 FrontierScience-Research 基准上胜过 GPT-6-Astra。这是"开源 = 落后半年"叙事的又一次松动：不是通用能力追平，而是**垂直领域的后训练可以让开源模型在特定科学任务上超过闭源旗舰**。
→ https://www.marktechpost.com/2026/11/02/deep-principle-hydrogen-1-0-open-weight-scientific-model/

**Drex Max v1：27B 本地决策模型**。Nace AI 开源，多模态，打分 67.52，能在 Apple Silicon 上本地跑。配合上周 Jev 引发的"决策模型"讨论，一条清晰的路线正在成形：**生成模型负责表达，决策模型负责在毫秒级做选择**，后者更适合本地、便宜、可嵌入。
→ https://www.marktechpost.com/2026/11/01/nace-ai-open-sources-drex-max-v1-local-inference/

**qwenGPU：把 GPU 编译进模型权重**。这个项目把 4-lane SIMT GPU 编译成 45 个未训练层塞进 Qwen3.5-2B，模型自己写出每一步 CUDA 启动，用 Gated DeltaNet 的状态当寄存器和内存。它更像一个"模型即运行时"的思想实验，但它拿到了 HN 与 MarkTechPost 的双重关注，说明社区对"权重不只是权重"这件事有真实兴趣。
→ https://www.marktechpost.com/2026/11/01/qwengpu-simt-gpu-compiled-into-qwen3-5-2b-weights-runs-cuda/

**Mistral Large 4（Le Chonk）的开源余波仍在**。HF 官方博客发布《Welcome Le Chonk》，确认 1T 总参 / 52B 激活、原生多模态、开放权重。WIRED 的说法是"法国实验室在编码与网络安全上跳过了中国开源模型"，而 Interconnects 的 Nathan Lambert 发了一篇自我质疑：《我在开源模型与网络风险上错了吗？》
→ https://huggingface.co/blog/mistral-large4
→ https://www.interconnects.ai/p/was-i-wrong-about-open-models-and

### 四、编码 Agent 的"下半场"：从能写代码，到能计费、能审计、能约束

Anthropic 公开了 Claude Code 团队的代码评审实践：**Claude 现在写了大约 90% 的代码**，团队里没有人保有完整的代码库心智模型；有一个 PR 在一夜之间跑了 50 多轮评审。InfoQ 的标题很克制——《Anthropic 说没人需要 Claude Code 的心智模型，实践者正在检验这句话》。
→ https://www.infoq.com/news/2026/10/anthropic-code-review/

配套的三个工具，恰好补上三个缺口：

- **成本**：微软研究院 + UC Berkeley 的 TokenEconomizer，从历史会话中学习，在 SWE-Bench 上把编码 agent 的 token 成本降低 18.4%–30.9%，且不改动 agent 本身。
  → https://www.marktechpost.com/2026/10/30/microsoft-tokeneconomizer-coding-agent-cost-control/
- **度量**：MIT TR 的《停止数 token，开始数交付》。一个 agent 任务的 token 消耗是普通对话的 10–50 倍，"越有用越贵"，所以 KPI 必须从 token 转向 shipped。
  → https://www.technologyreview.com/2026/11/02/1147702/stop-counting-tokens-start-counting-what-ships/
- **编排**：DeepSeek 开源 dsh-superagent（MIT），把 GitHub / 飞书请求转成并行 worker 会话，官方模拟中 p95 任务完成时间从 29.5 分钟降到 15.7 分钟。
  → https://www.marktechpost.com/2026/11/01/deepseek-dsh-superagent-router-worker-coding-agent/

另外两个值得记一笔：**Factory Droid 1.0** 把"程序化工具调用"设为默认，在自家 Terminal-Bench 4 上用 Claude Opus 5.5 拿到 65.2%，每个通过任务成本 $4.73；**Vercel Labs 的 agent-desktop** 用 Rust 写 CLI，通过操作系统无障碍树而不是像素让 agent 操作桌面，三平台通吃。
→ https://www.marktechpost.com/2026/10/31/factory-droid-1-0-frontier-harness/
→ https://www.marktechpost.com/2026/10/31/vercel-labs-agent-desktop-computer-use/

## 📰 行业深度

### 1. 《The agentic web is here》 — MIT Technology Review

2001 年 Berners-Lee 提出语义网，愿景是"由自主软件 agent 导航的互联网"；二十五年后，这个愿景以他最不愿看到的方式实现了：不是网站主动提供结构化语义，而是**模型自己去读、去点、去填表**。

文章的判断很硬：agent 正在把 Web 从"人读的文档集合"变成"机器执行的动作序列"，而现有的三层基础设施——身份、支付、权限——全部是为人类设计的。当 agent 替你下单、替你签约、替你提交表单，**"谁授权了什么"就成了比"页面长什么样"更根本的问题**。文章举的例子很具体：一个 agent 在电商站点上完成购买，需要跨越登录、支付、风控三道人类专属关卡，而今天每一道都是用"模拟人类"的方式绕过去的——这不是设计，这是欺骗。
→ https://www.technologyreview.com/2026/11/02/1147846/the-agentic-web-is-here/

### 2. 《Was I wrong about open models & cyber risks?》 — Interconnects

Nathan Lambert 罕见地写了一篇自我修正。他上个月创造"Black October"一词，形容一连串关键漏洞披露（PHP2Shell、GitLab 长期存在的 bug）标志"AI 模型的网络风险开始兑现"。一个月后他回头问：**这些漏洞真的是开源模型带来的，还是本来就在那里，只是 AI 让发现变快了？**

他的结论是分层的：AI 确实显著降低了漏洞发现的边际成本，但"开源 = 更危险"的推论站不住——因为攻击者用闭源模型同样有效，而防御方受益于开源模型的可审计性更多。真正的问题不是权重是否开放，而是**披露与修补的速度差**。这篇文章值得读，是因为它示范了一种在 AI 讨论里极度稀缺的东西：**在立场被记住之后，还敢改口**。
→ https://www.interconnects.ai/p/was-i-wrong-about-open-models-and

### 3. 《Egoless Mathematics in the AI Era》 — Terence Tao

陶哲轩谈的不是 AI 能不能做数学，而是**数学家该如何在 AI 时代组织协作**。他的核心观察是：当 AI 可以快速生成大量候选证明，传统数学文化里"谁先想到"的荣誉机制会失效，而"ego"（对原创性的执念）会成为协作的阻碍。

他提出的实践很有意思：把证明拆成可验证的小步，让 AI 负责搜索、人类负责判断"哪一步值得走"；并且明确区分"AI 辅助发现的定理"与"AI 独立证明的定理"在学术credit 上的不同处理。这篇在 HN 上 65 分、49 条评论，讨论的其实是一个更大的问题：**当产出变得廉价，判断力如何定价**。
→ https://terrytao.wordpress.com/2026/11/02/egoless-mathematics-in-the-ai-era/

## 📊 论文精选

### 1. Latent Sparse Attention: Towards Subquadratic Ultra-Long Context Attention
（arXiv 2610.42147）

超长上下文（>100 万 token）下，full attention 成本不可承受；现有稀疏注意力的问题是 **indexer 本身仍是二次复杂度**，或者精度在超长尺度上崩掉。LSA 的做法是把索引过程也搬到潜空间做稀疏化，从而在保持精度的同时把索引成本压到亚二次。同一天还有一篇 Zyphra 的层级树状索引器（2610.42112），从另一条路径逼近同一目标。**两篇撞车不是巧合——长上下文的瓶颈已经从"模型记不住"变成"算不起"。**
→ https://arxiv.org/abs/2610.42147v1
→ https://arxiv.org/abs/2610.42112v1

### 2. ID-WM: Hierarchical World Models with Implicit Dynamics
（arXiv 2610.42146）

具身智能做长程规划的两个老问题：误差累积、搜索空间爆炸。现有分层方法用"刚性宏动作"或"潜在技能"，导致表征脆弱、细粒度控制丧失。ID-WM 的关键设计是**把"状态空间可达性"与"局部控制"解耦**：高层模型只在可行转移之间采样，低层负责具体控制。这解决了分层 RL 里最经典的"高层指令不可执行"问题。
→ https://arxiv.org/abs/2610.42146v1

### 3. Same Question, Different Answers: Auditing Persona-Dependent Variation in Six LLMs
（arXiv 2610.42039）

对 6 个主流 LLM、12 种用户画像、4 个戒烟咨询问题，共 2880 次回答做审计。结论很直接：**同样的医学问题，模型给出的建议取决于"它以为你是谁"**——不同人生阶段、自述专业程度、吸烟史，都会显著改变建议内容与强度。在一个有明确临床指南的领域出现这种漂移，意味着"LLM 提供健康建议"的合规基础比想象中脆弱。
→ https://arxiv.org/abs/2610.42039v1

**补充一篇工程向的**：Flide（2610.42148）给决策模型（如 Jev）做精确状态分叉推理引擎，解决"生成式推理引擎跑决策任务时前缀重复计算"的问题——决策模型的推理栈正在被独立重建。
→ https://arxiv.org/abs/2610.42148v1

这条数据之所以重要，是因为它第一次把"AI 替代人力"这个抽象叙事换算成了一个可比的数字。过去我们说"AI 会取代工作"，讨论的是能力；现在有了一个真实的账本：**当 token 支出 > 薪酬支出，企业会怎么选？** 有三种可能。第一种，token 变得更便宜，账单自然回落——这正是 OpenAI 一周内两次降价、DeepSeek 开源 DeepInfer 在做的事。第二种，token 支出被计入"人力成本"科目，于是"雇人还是买 token"成为同一个预算里的两个选项——这会彻底改变 HR 与 IT 的边界。第三种，也是最可能的：**两者都不再单独核算，而是合并成"产出成本"**，那时企业真正关心的不是用了多少人、多少 token，而是每单位交付花了多少钱。

这也解释了为什么本周工具层突然集体转向"计费与审计"：TokenEconomizer 降成本 30%，MIT TR 喊"别数 token 数交付"，Uber 建 MCP Gateway 管 5000 个工具，Flide 给决策模型做专用推理引擎。**这些都不是能力突破，全部是记账基础设施。** 一个行业开始认真记账，通常意味着它从"讲故事"进入"交作业"阶段。

第二条线是安全，而且方向变了。本周四起事故，没有一起是"模型太聪明"。ChatGPT 账号接管是 Web 安全漏洞；Cursor 扩展后门是供应链；五角大楼那个 agent 是权限没登记；预训练投毒是数据链路。**换句话说，AI 安全的主战场已经从"对齐"转移到"软件工程基本功"。** 这对做工程的人是好消息：这些问题的解法——最小权限、制品签名、行为日志、schema 约束——都是过去二十年验证过的，只是需要被重新应用到 agent 上。

对克军，我给一个具体判断：**未来 12 个月最稀缺的岗位不是"会写 prompt 的人"，而是"能给 agent 建账本的人"**。这件事的本质是数据建模：agent 的每一次工具调用、每一次授权、每一次花钱，都要落成可查询的结构化记录；再往上才是可观测性、成本归因、合规审计。数据库背景在这里不是加分项，是核心能力。

最后一句：今天这份日报有 76 条，但真正需要在周二上午做决定的可能只有一条——**你手上的 agent，能不能在月底给你一张账单，说清楚它这个月替你干了什么、花了多少、哪一笔不划算。** 如果答不上来，那你现在做的不是 agent 工程，是 agent 试用。
