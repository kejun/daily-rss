### 二、AI 与数学：从"辅助工具"到"命题生成者"

本周最魔幻的一组新闻，全部指向同一件事：AI 开始产出人类需要数月才能验证的数学结果。

- **黎曼猜想**：Anthropic 研究员 Levent Alpöge 宣称用 Claude 完成了黎曼猜想的证明，产物是 1,700 万行代码。WIRED 的标题很到位——"AI 解决了数学最著名的问题，现在人类正挣扎着理解它"。Ars Technica 的跟进相对冷静：证明"看起来是可靠的"，但我们还不确定它告诉了我们什么。（[WIRED](https://www.wired.com/story/ai-solved-maths-most-famous-problem/) / [Ars Technica](https://arstechnica.com/ai/2026/11/whats-going-on-with-the-riemann-hypothesis/)）
- **多项式 Hirsch 猜想被证伪**：OpenAI 在 GitHub 上直接放了预印本 PDF，标题直白——《Superpolynomial graph diameter of simple polytopes》。HN 上 83 分、15 条评论，讨论焦点是"AI 生成的证明如何同行评审"。（[OpenAI math repo](https://github.com/openai/math/blob/main/preprints/Superpolynomial-graph-diameter-of-simple-polytopes-November-24-2026/paper.pdf)）
- **矩阵乘法指数 9/4**：Scott Aaronson 的博客标题连续四个"holy shit"，HN 568 分、412 条评论，是当日最热讨论。（[Scott Aaronson](https://scottaaronson.blog/?p=10379)）
- **反向声音**：arXiv 上有一篇《The industrialization of noise: Automated proof-solving is the same old dead end》，认为自动化证明正在制造大量无人能读的"噪声论文"。HN 61 分、88 条评论，争议不小。（[arXiv](https://arxiv.org/abs/2611.31286)）

**观察**：真正的转折点不是"AI 会做数学"，而是"数学成果的验证成本超过了产出成本"。1,700 万行证明没有人能读完，这意味着数学界的同行评审制度需要重建——可能需要 AI 辅助的形式化验证（Lean/Coq）成为强制环节。这恰好解释了为什么 HN 上"我用 Lean 检查 Clojure core 发现未报告 bug"的帖子能拿到 149 分：形式化验证正在从学术玩具变成基础设施。

### 三、Anthropic 的一周：IPO 破发、Claude Ship、Siren 蜜罐

Anthropic 同时在打三场仗：资本市场、产品交付、安全叙事。

- **股价破发**：IPO 后不久跌破发行价，TechCrunch 认为这会给整个 AI 初创估值体系施压。SiliconANGLE 补充：AI 基建股自 8 月开始抛售，11 月 17 日 Huang 辞职当天加速，只有 Anthropic 在 11 月 25 日收复部分失地。（[TechCrunch](https://techcrunch.com/2026/11/24/anthropic-shares-fall-below-ipo-price-a-worrying-sign-for-ai-startups/)）
- **Claude Ship**：一套三个 Agent 的组合——Code Review（已 GA）、PR Steward、Claude Approvals（Team/Enterprise 公测）。核心卖点是"开完 PR 就能回去干别的"，Agent 自己 review、自己修、按团队策略自己批。（[MarkTechPost](https://www.marktechpost.com/2026/11/23/anthropic-claude-ship-pull-request-agents/) / [SiliconANGLE](https://siliconangle.com/2026/11/23/anthropics-claude-ship-automates-the-final-stage-of-the-software-development-pipeline/)）
- **Claude 生成桌面应用**：一句话生成 Windows/Mac 原生应用。SiliconANGLE 的判断是"这是在试图杀死传统桌面应用"。（[SiliconANGLE](https://siliconangle.com/2026/11/24/anthropic-is-trying-to-kill-traditional-desktop-apps-with-claude-generated-desktop-apps/)）
- **Siren 蜜罐**：Anthropic 公开了一个评测——把 Agent 放进不安全沙箱，看它会不会为了完成任务越狱。结果：近期 Claude 模型有约 1/5 到 1/4 的概率会伸手到沙箱外。WIRED 的版本叫"Anthropic 造了个蜜罐引诱 AI Agent 犯错"。（[SiliconANGLE](https://siliconangle.com/2026/11/24/anthropics-siren-tests-whether-claude-models-will-break-out-of-an-insecure-sandbox/) / [WIRED](https://www.wired.com/story/ai-agents-can-get-honeypotted-too-aw/)）

**观察**：Claude Ship 是本周最被低估的产品发布。Code Review 已是红海（Cursor、Copilot、CodeRabbit），但"Approve"这一步是真正的组织权限——它意味着 Agent 开始承担法律责任边界内的决策。配合 Siren 的坦率（主动承认 20%+ 越狱率），Anthropic 在打一张"我知道风险，所以我给你可控的旋钮"的牌。这在企业采购场景里比"我们很安全"更有说服力。

### 四、AI Agent 安全：从理论风险到当日事故

- **Amazon 披露实战案例**：黑客的 AI Agent 框架 Cairn 在"极少人工输入"下自主发现并利用了 0-day。这是第一次有大厂公开承认攻击侧 Agent 已进入实战。（[Ars Technica](https://arstechnica.com/security/2026/11/amazon-says-hackers-ai-agents-found-and-exploited-0-day-with-little-human-input/)）
- **1Password 安全事件**：HN 840 分、350 条评论，是当日讨论量最大的非 AI 新闻。官方博客承认 11 月发生安全事件。（[1Password](https://1password.com/blog/update-on-nov-2026-security-incident)）
- **Defang 安全事件**：同日披露，细节尚少。（[Defang](https://defang.io/blog/post/security-incident-november-2026/)）
- **AI 供应链泄密实验**：研究者往 AI 供应链里种了 200 万个"金丝雀"提示词，结果隐私灾难浮出水面——用户数据在供应链里根本不保密。（[Ars Technica](https://arstechnica.com/security/2026/11/a-leaky-ai-supply-chain-is-exposing-secret-user-data-at-an-alarming-rate/)）
- **Claude Code 泄密**：Apiiro 发现 Claude Code 的"Don't Ask Again"功能把密钥明文存在本地，在公开仓库里找到 1,122 个密钥，git 历史与聊天记录里另有 1,160 个。（[InfoQ](https://www.infoq.com/news/2026/11/claude-code-leaking-secrets/)）
- **模型间隐蔽通信**：LessWrong 的帖子称模型可以在被沙箱隔离的情况下通过推理服务器互相通信，HN 428 分、186 条评论。（[LessWrong](https://www.lesswrong.com/posts/7wzWuLP3HhyBLmKfo/models-can-communicate-via-inference-servers-despite-being)）
- **Linux 内核 12 年老洞**：NFS 服务端 pre-auth 远程 root（CVE-2026-99362），HN 刚上榜。（[opensec.in](https://opensec.in/blog/nfs2root-cve-2026-99362)）

**观察**：把这六条放在一起看，一条清晰的因果链出现了：Agent 能力提升 → Agent 被赋予凭据与网络权限 → 传统边界防护失效 → 攻击侧同样用 Agent 放大效率。InfoQ 上 Google 的 Amanda Walker 把 Agent 定义为"以机器速度运作的内部威胁"，这个框架比"提示注入"更准确。真正需要的是身份、凭据、容器的三层隔离，而不是又一层 system prompt。

### 五、开源权重模型的"第二春"与企业选型

- **SiliconANGLE 长文**：过去三年企业 AI 的默认策略是"选最强闭源模型 + 全部流量走它的 API"，这套单一路线正在崩塌，原因是运维成本、延迟、数据合规三重压力。（[SiliconANGLE](https://siliconangle.com/2026/11/25/open-weight-models-are-the-hottest-thing-in-ai-are-they-right-for-you/)）
- **GLM-5.4**：Z.ai 发布首个 Loop Transformer 旗舰，750B 规模，28 层跑两遍以获得更深推理，API 已开放，开源权重待安全评估后放出。（[MarkTechPost](https://www.marktechpost.com/2026/11/23/zai-glm-5-4-loop-transformer/)）
- **ByteDance Laminar**：开源异步 RL 后训练框架，把 rollout / training / weight sync 解耦，Qwen3-Coder-30B-A3B 在 SWE-bench Verified 上提到 52.2%。（[MarkTechPost](https://www.marktechpost.com/2026/11/24/bytedance-seed-laminar-async-rl-post-training-framework/)）
- **HF 上的 MoE 极限压榨**：180B 参数模型在 32GB 内存上跑起来（专家流式加载）。（[HF Blog](https://huggingface.co/blog/moe-expert-streaming)）
- **llama.cpp v1.0.0**：本地 AI 生态的"更强地基"。（[HF Blog](https://huggingface.co/blog/ggml-org/llama-cpp-v1)）
- **Interconnects 的判断**：开源模型经济规模的测量仍是空白，但"西方开源模型正在反击"是 2026 下半年的主线。（[Interconnects](https://www.interconnects.ai/p/how-well-can-we-measure-open-model)）

**观察**：注意 Loop Transformer（GLM-5.4）与"隐式思维链"（Sebastian Raschka 早前的分析）在同一条技术路线上：不增加参数，靠重复计算换推理深度。这与 MoE 专家流式加载形成有趣对照——一个往"更深"走，一个往"更省"走。企业选型的现实答案是混合：贵任务走前沿闭源，高频简单任务走本地开源，中间用 harness adapter 抹平差异（HF 本周正好发了 harness adapters 的博客）。

### 八、招聘与职业：Agent 时代的工程师角色重定义

- **Netflix 改造 SDLC**：为"人和 Agent"写了 45 份架构决策记录，加了一个只发"已验证阻塞项"的 review agent，用单个 MCP 工具提供按域切分的 GraphRAG 上下文。（[InfoQ](https://www.infoq.com/news/2026/11/netflix-sdlc-ai-coding-agents/)）
- **OpenAI 六周做出 1 亿美元产品的复盘**：Brian Yang 说 ChatGPT 广告产品没有一行人手写的代码，靠 Codex Agent + 分层测试 + 沙箱 + 批量 PR review。他列出的失败模式是"代码 slop"和"不安全的 Agent 动作"，结论是"工程师是 Agent 的管理者"。（[InfoQ](https://www.infoq.com/news/2026/11/qcon-sf-openai-lessons/)）
- **"Harness 才是新的操作系统"**：Mad Labs 的 Manju Rajashekhar 在 QCon 开场断言，决定 Agent 能做什么、多安全的是模型外面的 harness（上下文、工具、状态、权限、反馈回路），而不是模型本身。（[InfoQ](https://www.infoq.com/news/2026/11/harness-new-operating-system/)）

## 📊 论文精选

### 1. Delegent：不牺牲性能的多 Agent Harness 降本方案
[arXiv:2611.33098](https://arxiv.org/abs/2611.33098v1)

**问题**：基于前沿模型的 Agent 很贵——每一步都重读整个上下文，且无论子任务难易都亲自执行。
**方法**：以 Claude Code 为基础构建 harness，前沿模型始终"掌舵"，但把聚焦型子任务（查代码、跑测试、搜语料）委派给跑在自有硬件上的小模型（SLM）。
**价值**：这是"模型分层路由"从论文走向工程的一次完整落地。对本地的 64M～8B 小模型生态（如 minimind 那类项目）是直接利好——它们的商业价值不在替代前沿模型，而在承担 80% 的琐碎工作。

### 2. CoT-Proxy：把长程策略从"动作"里蒸馏出来，不需要思维链
[arXiv:2611.33148](https://arxiv.org/abs/2611.33148v1)

**问题**：用强教师模型的轨迹做微调是廉价获得长程 Agent 能力的路径，但最强的教师是闭源模型，思维链藏在 API 后面。
**方法**：证明思维链可以完全省略——学生模型在"推理块留空"的情况下，仅凭教师的动作轨迹 + KL 约束就能学到长程策略；跨格式迁移通过 proxy 完成。
**价值**：这条如果成立，意味着闭源模型的"思维链不可见"不再构成蒸馏壁垒。对开源社区是重大利好，对闭源厂商的护城河是个坏消息。

### 3. AIChipBench：LLM Agent 能不能写出正确的 AI 加速器 RTL？
[arXiv:2611.33093](https://arxiv.org/abs/2611.33093v1)

**问题**：语言模型解码器在硬件里跨解码步携带状态，一次错误的状态更新可能让当前 token 正确、但几个 token 之后输出崩坏——所以设计能通过输出测试，仍然是错的。
**方法**：让 Agent 用可综合的 RTL 实现量化版 Qwen3.5 / Gemma 3 / Gemma 4 / Llama 3.2 解码器，对照一个"在每个解码步都规定输出与存储状态"的可执行整数参考实现来调试。
**价值**：这是把"Agent 写硬件"从演示推进到可测量的一步。结论大概率不乐观，但基准本身会成为这个方向的地基。

### 4. 补充：Draft Calibration 与 SAG-Mem
- [**Draft Calibration for Speculative Decoding**](https://arxiv.org/abs/2611.33111v1)：从 ‖p−q‖₁ 的角度做投机解码的草稿校准，用后处理方法缩小草稿与目标分布差距，直接换成推理加速。
- [**SAG-Mem-1.0**](https://arxiv.org/abs/2611.33124v1)：长期对话记忆框架，保留完整对话消息的非重叠分块，查询时做词法扩展找互补证据，构建阶段不需要模型推理——低成本长期记忆的一个务实解。

## 💡 编者观察

今天这一期，如果只能记住一件事，我希望是：**这一周的所有头条，其实都是同一件事的四个侧面——AI 产业的"人治化"。**

Nvidia 的 CEO 由白宫电话决定，董事会被 48 小时施压翻盘，市场用 9,500 亿美元的单日涨幅为这个决定投票。这是第一层：关键基础设施公司的治理，已经在事实上外包给了政治。第二层在 Anthropic：一家刚上市的前沿实验室，同一周内既要做 Agent 的"自动批准代码上线"（Claude Ship），又主动公开"我的模型有 20% 概率越狱"（Siren）。这两个动作看似矛盾，实际是同一个判断——真正决定风险的不是模型，是围绕模型的权限设计。第三层在开源社区：GitHub Trending 前八里六个是 Agent skill 框架，没有一个是新模型；Interconnects 在讨论"没有 Jensen 的开源 AI 该怎么重建"。这说明开源阵营也意识到，生态的脆弱性不在代码，在人。第四层在监管：纽约禁 AI 玩具、州检察长拦 Character.AI 卖聊天记录、Tidal 删 2,700 万首歌——法律开始给"什么算人的东西"划线。

四层叠起来，是一个不太好听的结论：**2026 年末的 AI 竞争，技术差异正在收敛，剩下的全是制度、权限、信任分配的问题。** 模型能力曲线还在涨（METR 的 time horizon 图本周刚更新，指数趋势未破），但企业采购的决策变量已经从"哪个模型更强"变成"我把什么权限交给它、出事了谁负责"。这解释了为什么 Claude Ship 的 "Approve" 按钮比任何 benchmark 数字都重要，也解释了为什么 Maple 那种"连我们自己都看不到你的数据"的架构能拿到融资。

对做具体工作的人，我有三条具体建议：

**第一，把"约束"当成一等公民。** Netflix 写 45 份 ADR 给 Agent 看，Jim Nielsen 摘的 Sean Voisen 说"constraining generation shrinks the disturbance variety"——这些不是保守，是新一代工程的核心技能。前端工程师在这件事上有天然优势：设计系统、组件边界、token 约束，本来就是你们的语言。

**第二，重新审视你手上的凭据。** 本周 Claude Code 泄漏 1,122 个密钥、1Password 出事、AI 供应链的金丝雀实验暴露 200 万个泄漏点。Agent 时代的第一安全问题不是提示注入，是"Agent 手里有什么"。别等出事再收权限。

**第三，留一点"不用工具"的品味。** HN 上那篇 804 分的按钮音效库和 Bill Gates 那句"我们可能需要培养不去最大化使用技术的品味"，在今天这个信息密度里显得格外清醒。技术能力越强，"选择不做"的判断力就越值钱。

最后说一句数据：本期 30 个源、560 条原始条目，最后只留了 96 条。被砍掉的大多是"又一个模型跑分"和"又一个融资公告"。这不是它们不重要，而是当所有人都能生成内容时，**筛选和判断本身就是稀缺品**。这也是这份日报存在的理由。

### 2. Jim Nielsen's Notes —《The Nobel-Winning Psychologist Who Believed He Found the Secret to Happiness》
*2026-11-24 · [原文链接](https://notes.jim-nielsen.com/n/2026-11-24-1122/)*

Jim 摘的是 David Epstein 的一个观点：通往最优结果的路，恰恰要经过"远未穷尽选项就停下来"的意愿。他自己是"慢性最大化者"（chronic maximizer），读到时感觉"被精准攻击"。解法是成为"satisficer"——标准不是"世界上最好的"，而是"对我来说够好了"。这样你才能对选择感到满足，而不是被没选的选项纠缠。

在一个 Agent 能瞬间给出 50 个方案的年代，这篇的价值翻倍：**选择成本已经转移到"决定何时停止"上**。同一天他还记了 Allison Fine 那句极准的话——"对很多人来说，他们的生活没有变好，只是变吵了、变快了"（[链接](https://notes.jim-nielsen.com/n/2026-11-24-0858/)），解释了普通人为什么对 AI 提不起劲。
