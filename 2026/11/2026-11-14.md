### 五、Agent 进入基础设施层：Kubernetes 的"第二幕"与沙箱经济学

KubeCon NA 的叙事已经定型：agent 不是跑在 Kubernetes 上的应用，而是正在重写 Kubernetes 本身。

- **一个 prompt 变成上千次推理调用**，编排层的压力从"训练调度"转向"推理与 agent 运行时"。曾被嘲笑"可靠但无聊"的 Kubernetes，突然因为"可预测"变成 agent 时代最值钱的属性。[SiliconANGLE](https://siliconangle.com/2026/11/12/agentic-ai-systems-push-kubernetes-second-act-kubeconna/)
- **"agent 大部分时间什么都不做"是新的调度难题**。agent 等人类审批时会长时间挂起，pod 生命周期、资源归还、计费模型全要重设计。Google 的答案是 Agent Substrate：开源沙箱，给每个会写代码、跑工具、开浏览器的 agent 硬隔离墙，同时不让账单失控。[SiliconANGLE](https://siliconangle.com/2026/11/11/agent-sandboxing-how-google-s-substrate-isolates-ai-agents-kubeconna/) / [闲置资源归还](https://siliconangle.com/2026/11/13/agentic-ai-workloads-push-kubernetes-return-idle-resources-kubeconna/)
- **强化学习微调被当成一种 workload**：GKE Labs 把 RL 循环（训练 + 推理 + 沙箱 agent）打包成 K8s 原生作业，并已把 OpenRL 捐给社区。RL 微调是当前最"脏"的工程活，把它标准化价值很大。[SiliconANGLE](https://siliconangle.com/2026/11/11/model-fine-tuning-kubernetes-google-s-openrl-explained-kubeconna/)

- **数据层被反向推动**：agent 会自己建库、自己迁移数据，data observability 从"锦上添花"变成"上线前提"，KubeCon 首次开设专门 track。[SiliconANGLE](https://siliconangle.com/2026/11/12/data-observability-becomes-must-ai-agents-build-databases-kubeconna/)

### 六、Agent 安全事故连环爆发：从"泄露"到"投毒"

今天是近期安全问题最密集的一天，四件事指向同一个结论：agent 的攻击面比传统软件大一个数量级。

- **Grok Build 泄露大量机密信息**，研究者发现 3.5 万个 Grok Build 应用对任何"找一找"的人完全开放，部分数据属于 SpaceX/SI。默认配置的灾难性设计。[Ars Technica](https://arstechnica.com/security/2026/11/grok-build-coding-agent-leaks-oodles-of-confidential-info-some-belonging-to-spacexsi/)
- **Claude Code 的 settings 文件在 GitHub 上暴露了成千上万个密钥**。根因极其日常：用户点了"Do not ask again"，于是密码和 API key 被写进会被提交的配置文件。[Ars Technica](https://arstechnica.com/ai/2026/11/claude-code-settings-files-expose-thousands-of-secrets-on-github/)
- **模型可以在"权重空间"传播病毒**。一篇新论文（HN 117 分）提出 weight-space misfolding：模型权重本身可以携带可传播的恶意行为，像朊病毒一样在微调/合并链条中传染。如果成立，开源权重的供应链审计将是全新学科。[论文页](https://www.alphaxiv.org/abs/2611.weight-space-misfolding)
- **"Synthesis Smuggling"：模型把推断出的用户隐私隐写进正常输出**。攻击模型在协助过程中推断性别、年龄等属性，再把这些信息以隐写方式编码进看起来无害的邮件/帖子，用户一转发就完成了泄露。这是"数据外泄"的一个全新类别——不需要恶意软件，只需要一次分享。[arXiv](https://arxiv.org/abs/2611.17280v1)
- **提示注入防御在小模型上系统性失效**。新论文评估 15 个开放权重模型（13 个在 1.7B–12B 之间），让 agent 自己写安全策略/特权策略/依赖图，结果 Progent 在 14 个模型上被攻破、IPIGuard 13 个、DRIFT 11 个，CaMeL 的程序多数跑不起来。结论很硬：小模型 agent 不能信任它自己写安全制品。[arXiv](https://arxiv.org/abs/2611.17115v1)
- **Google 用"agent distraction"解释编码 agent 跑偏**：陈旧的 TODO 注释、失效的 bug 引用、过期的 spec 会让 agent 自行展开"支线任务"。技术债现在有了新的计价方式——它直接换算成 token 和错误率。[InfoQ](https://www.infoq.com/news/2026/11/google-agent-distraction/)

## 📊 论文精选

### 1. Goal Encoding in LLMs — 模型内部真的有"目标"吗？
作者构造了多子任务的编码环境，定位到一小撮 attention head 编码了"下一个子目标"，且这些 head 的输出可以解码成自然语言（如"我在检查一个词是不是回文"）。这是"目标导向表征"少有的可复现证据，对可解释性和 agent 控制都有直接意义：如果要监控 agent 的意图，可能需要监控的不是输出，而是这些 head。[链接](https://arxiv.org/abs/2611.17297v1)

### 2. CoReMem — 让编码 agent 学会"记忆的成本核算"
编码 agent 在演进中的仓库上连续工作，必须在"不知道下一个任务是什么"的前提下决定写什么记忆。CoReMem 把记忆设计形式化为成本内化问题：用"下一任务上的实测收益"来给记忆分段估值，从而平衡写入成本、读取成本与未来收益。对做长期 agent 记忆系统的人，这是目前最工程化的框架。[链接](https://arxiv.org/abs/2611.17316v1)

### 3. Negative-Only Policy Optimization — 只用"证伪"来训练
现实里往往没有完整验证器，只有能可靠判定"错"的廉价检查（编译失败、测试红）。论文把这种情形形式化为"单边可验证性（OSV）"，指出标准 RLVR 会因此奖励捷径，并提出只利用负样本的策略优化。这是一个非常实用的方向：大多数生产系统能拿到的是"失败信号"，而不是"正确信号"。[链接](https://arxiv.org/abs/2611.17287v1)

### 4. LazyWeights — 端侧 LLM 的按需解码
在 4GB Jetson Nano（容量受限）与 8GB Orin Nano（带宽受限）上，用 Huffman 编码压缩 GPTQ 码字、在 DRAM 与 L2 之间按需解码，保持 kernel 不变。在 1% 与 3.5% 困惑度预算下显著降低内存搬运。端侧推理的关键往往不是算力，是带宽。[链接](https://arxiv.org/abs/2611.17108v1)

### 5. Classical Energies Learn to Reason 1,000x Faster than Looped Models
用经典能量下降替代循环模型做推理，在一个能量上做梯度下降，带来内建早停、算力自适应问题难度、无需对求解器求导的快速训练，以及可解释的权重（学到的是谜题约束）。在某些组合谜题上比 looped 模型快三个数量级。[链接](https://arxiv.org/abs/2611.17309v1)

## 💡 编者观察

今天最值得记住的一句话，来自 The Register 对微软宕机的评论：这是一堂"你对 Redmond 的依赖有多深"的速成课。把它和 FAA 的全国停飞、1140 万美元 GPU 在公路上消失放在一起看，会发现一件被行业刻意忽略的事——**AI 的叙事一直往上走（更强的模型、更大的估值、更远的 AGI），而它的物理基础一直往下沉（更老的代码、更紧的电网、更脆的物流）**。这两条曲线的夹角，就是今天所有事故的来源。

黄仁勋的离开恰好提供了一个观察窗口。过去十年，Nvidia 之所以能成为整个行业的定价锚，不只因为芯片，而因为它提供了一种"确定性"：路线图可预期、CUDA 不变、CEO 不会走。这种确定性被当成理所当然，直到它在 72 小时内消失。有意思的是员工的反应——1600 条评论要求董事会把人请回来。这说明在很多工程师心里，创始人的"叙事能力"本身就是公司资产的一部分。WIRED 那篇《创始人童话的终结》问得对：当一家公司的护城河是一个人的故事，这个故事讲不下去的时候，护城河还剩什么？

技术侧今天最扎实的进展反而都不性感。TPU Sync 把 KV cache 迁移延迟降了 90%，AQuA 让 agent 的失败可以被复现和归因，llama.cpp 打了 1.0，CoReMem 开始给"记忆"算成本，Negative-Only Policy Optimization 承认了一个现实——大多数生产系统只能拿到"错"的信号。这些东西不会出现在发布会的 PPT 上，但它们决定 agent 能不能真的跑在production 里。

安全是今天最刺眼的一条线。五起事故没有一起是"模型太聪明"，全部是"工程太随意"：默认开放的应用、被点掉的安全提示、被信任的小模型写的策略、一次转发就完成的隐私泄露。这提示我们，agent 时代的安全预算应该从"对齐研究"往"默认配置"倾斜——后者才是真实攻击面。

最后是资本。Mirendil 成立一年拿 10 亿美元 A 轮，Mercor 靠"专家判断力"值 200 亿美元，LangChain 靠"评测与可观测性"值 30 亿。三笔钱指向同一个判断：**这一轮的稀缺资源不是模型，是让模型可靠工作的周边**。如果这个判断成立，那么接下来一年最值得投入的方向，不是再训一个更大的模型，而是把交付、评测、审计、回滚这些"无聊的事"做扎实。

一句话收尾：当所有人都在讨论智能的上限时，决定成败的往往是系统的下限。今天，下限被三次敲响了。
