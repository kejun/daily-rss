### 🔥 核心主题聚合

#### 🤖 AI 辅助编程与 Agent 工程

今日多篇内容聚焦于 AI 编码代理（coding agents）在实际工程中的应用，标志着"Agentic Engineering"正在成为新的工程范式。

**Ladybird 浏览器采用 Rust，借助 AI 完成迁移**  
**来源**: Simon Willison's Weblog | **作者**: Andreas Kling  
🔗 <https://simonwillison.net/2026/Feb/23/ladybird-adopts-rust/>

这是一个高级编码代理应用的典型案例研究。Ladybird 团队在希望 Swift 平台支持多年未果后，转向 Rust 作为内存安全语言的选择。Andreas Kling 使用 Claude Code 和 Codex 完成了 LibJS（JavaScript 引擎）的移植：

- **规模**: 约 25,000 行 Rust 代码
- **时间**: 两周完成（手动完成需数月）
- **方法**: 人类指导，非自主生成。通过数百个小提示引导代理
- **质量保证**: 依赖 test262 一致性测试套件，确保字节级输出一致
- **结果**: 零回归，所有 AST 和字节码与 C++ 版本完全一致

**关键洞察**: 高质量的一致性测试套件是此类大规模 AI 辅助迁移项目的关键解锁因素。

**Agentic Engineering Patterns 新项目启动**  
**来源**: Simon Willison's Weblog  
🔗 <https://simonwillison.net/guides/agentic-engineering-patterns/>

Simon Willison 启动了新项目，旨在收集和记录"Agent 工程模式"——帮助开发者在这个编码代理新时代获得最佳实践。

**核心定义:**
- **Agentic Engineering**: 使用编码代理构建软件（如 Claude Code、OpenAI Codex），特点是能够生成并**执行**代码，独立测试和迭代
- **Vibe Coding**: 完全不看代码的编程方式，常与非程序员使用 LLM 写代码相关
- **Agentic Engineering**: 专业软件工程师使用代理放大现有专业知识

**已发布章节:**
1. [Writing code is cheap now](https://simonwillison.net/guides/agentic-engineering-patterns/code-is-cheap/) - 讨论核心挑战：生成初始工作代码的成本几乎为零，如何影响个人和团队的工作直觉
2. [Red/green TDD](https://simonwillison.net/guides/agentic-engineering-patterns/red-green-tdd/) - 描述测试优先开发如何帮助代理用最少的提示写出更简洁可靠的代码

**计划**: 每周发布 1-2 章，持续更新。采用"guide"新内容格式，章节设计为可随时更新的常青内容。

**代码现在很便宜**  
**来源**: Agentic Engineering Patterns 第一章  
🔗 <https://simonwillison.net/guides/agentic-engineering-patterns/code-is-cheap/>

采用 Agent 工程实践的最大挑战是接受"**写代码现在很便宜**"这一事实带来的后果：

**传统约束被打破:**
- 宏观层面：项目设计、估算和规划的传统流程受到冲击
- 微观层面：重构、文档、测试、调试接口等决策的权衡需要重新评估
- 并行代理能力使一个工程师可同时在多处实现、重构、测试和文档化

**好代码仍有成本:**
- 代码能正常工作且无 bug
- 我们**知道**代码能工作（有验证步骤）
- 解决了正确的问题
- 优雅处理错误情况
- 简单最小化
- 有测试保护
- 适当文档化
- 设计支持未来变更
- 满足相关的"ility"（可访问性、可测试性、可靠性、安全性等）

**建议**: 培养新的个人和组织习惯。当直觉说"不值得花时间"时，仍可在异步代理会话中尝试，最坏情况只是浪费一些 token。

#### 🛠️ Web 开发工具链演进

**用 Web Origami 简化图标集管理**  
**来源**: Jim Nielsen's Blog  
🔗 <https://blog.jim-nielsen.com/2026/origami-icons/>

探讨了如何在博客中优雅地管理 Heroicons 图标集：

**传统方法的痛点:**
- 手动复制粘贴 SVG 到 HTML
- 或创建本地文件 + Node.js 读取样板代码
- npm 包安装大量不需要的图标
- 切换图标集时需要更新所有引用

**Origami 解决方案:**
```ori
{
  home.svg: https://raw.githubusercontent.com/tailwindlabs/heroicons/refs/heads/master/optimized/24/outline/home.svg,
  about.svg: https://raw.githubusercontent.com/tailwindlabs/heroicons/refs/heads/master/optimized/24/outline/question-mark-circle.svg,
  search.svg: https://raw.githubusercontent.com/tailwindlabs/heroicons/refs/heads/master/optimized/24/outline/magnifying-glass.svg
}
```

**优势:**
- 无需 npm install 或 git submodule
- 通过 URL 声明依赖，网络获取
- 支持本地缓存到磁盘
- 轻松切换图标集（只需修改映射文件）
- 符合"webby"风格，类似 Deno 的 HTTP imports

**深层意义:** 这不是语言特性，而是语言表达力的自然结果。Origami 推动开发者用"web 平台"思维而非抽象层思考问题。
