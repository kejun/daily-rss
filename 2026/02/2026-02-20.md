### 主题一：Prompt Caching 成为 Agent 产品的关键技术

**Thariq Shihipar：Claude Code 的提示缓存策略**

在 X 平台上，Claude Code 团队的 Thariq Shihipar 分享了 prompt caching（提示缓存）对于长期运行的 Agent 产品的重要性：

> "Long running agentic products like Claude Code are made feasible by prompt caching which allows us to reuse computation from previous roundtrips and significantly decrease latency and cost."

他透露，Claude Code 的整个 harness 都是围绕 prompt caching 构建的。高提示缓存命中率不仅降低成本，还能帮助为订阅计划创建更慷慨的使用限制。因此团队会对提示缓存命中率设置警报，如果过低甚至会宣布 SEV（严重事件）。

**为什么重要：** 这揭示了生产级 AI Agent 系统背后的工程细节。当大家都在讨论"Vibe Coding"和 Agent 能力时，真正让这些产品可行的是底层的工程优化——特别是计算复用和成本控制。

### 主题二：复古计算的浪漫时刻

**15 年前的今天：VIC-20 首次发推**

2010 年 2 月 20 日，加拿大个人电脑博物馆馆长 Syd Bolton 做了一件前无古人的事：让一台 Commodore VIC-20（1982 年最畅销的电脑）发送了一条 Twitter 消息。

这台运行在 1MHz 处理器、仅 5KB RAM 的古老机器，通过串口连接现代设备，成功将消息发送到当时如日中天的社交平台。这个行为艺术式的项目展示了计算历史的传承——从 8 位时代到社交网络时代，再到今天的 AI 时代。

**有趣的事实：** VIC-20 是历史上第一台销量突破百万的个人电脑，比 Commodore 64 更早普及家庭计算概念。

## 💡 编者观察

今天的两条内容看似跨度很大——一条是关于最前沿的 AI Agent 工程优化，另一条是 15 年前的复古计算趣闻。但它们共同指向一个主题：**技术的延续性**。

1. **Prompt Caching 的本质**：这不是什么新发明，而是计算机科学中经典的"缓存"思想在 LLM 时代的应用。就像 CPU 缓存、Web 缓存、数据库查询缓存一样，prompt caching 解决的是重复计算的成本问题。不同的是，这次被缓存的是 token 序列和注意力计算结果。

2. **复古计算的启示**：VIC-20 只有 5KB 内存，却能完成"发推"这样的网络操作（通过外部设备辅助）。这提醒我们，即使在资源极度受限的环境下，创造性思维也能找到突破口。今天的 AI 开发者面临类似的挑战——如何在有限的 context window 和 token 预算内，实现更强大的功能？

3. **工程与艺术的平衡**：Claude Code 团队把 prompt cache hit rate 当作 SEV 指标来监控，这是严肃的工程实践。而 VIC-20 发推则是纯粹的技术艺术。优秀的技术生态需要两者并存——既有严谨的性能优化，也有浪漫的探索精神。

**思考题：** 如果你的 AI Agent 只能使用 5KB 的"记忆空间"，你会如何设计它的认知架构？
